# ТЗ: Кэшбэк по выбранным категориям для дебетовых карт

Версия 0.4 (черновик) | Подготовил: Департамент розничного бизнеса | Дата: 26.11.2026

## 1. Назначение

Документ описывает требования к функционалу «Кэшбэк по категориям» для держателей дебетовых карт Банка (физические лица, резиденты РК). Клиент ежемесячно выбирает категории покупок в мобильном приложении и получает кэшбэк деньгами на карточный счёт в тенге.

Цели:
- повысить долю безналичных покупок по картам Банка;
- увеличить ежемесячную активность клиентов в мобильном приложении;
- заменить действующую бонусную программу «Плюс» (закрывается 01.03.2027).

Вне рамок: кредитные и корпоративные карты, бонусы партнёров, операции в иностранной валюте.

## 2. Термины и сокращения

| Термин | Описание |
|---|---|
| Категория | Группа торговых точек, объединённых по MCC-кодам (например, «Кафе и рестораны», «АЗС») |
| Отчётный месяц | Календарный месяц, за покупки в котором начисляется кэшбэк |
| Окно выбора | Период, в который клиент выбирает категории на следующий месяц |
| Начисление | Зачисление суммы кэшбэка на карточный счёт клиента |
| CBS | Cashback Service, новый микросервис программы |
| ПЦ | Процессинговый центр (Way4) |
| АБС | Автоматизированная банковская система (Colvir) |

## 3. Участники и роли

| Роль | Описание |
|---|---|
| Клиент | Держатель дебетовой карты Банка, пользователь мобильного приложения |
| CBS | Хранит выбор категорий, рассчитывает кэшбэк и инициирует начисление |
| ПЦ | Формирует реестр операций по картам за отчётный месяц |
| АБС | Проводит зачисление кэшбэка на карточный счёт |
| Маркетинг | Настраивает категории, ставки и лимиты в админ-панели CBS |
| Контакт-центр (КЦ) | Просматривает историю начислений в CRM по обращению клиента |

## 4. Функциональные требования

### 4.1 Подключение и выбор категорий

**ФТ-01.** Клиент подключается к программе один раз: при первом входе в раздел «Кэшбэк» нажимает кнопку «Подключить» и принимает условия программы.

**ФТ-02.** В окно выбора клиент видит список категорий на следующий месяц со ставками. Клиент может выбрать до 3 категорий. Ставка по каждой категории фиксирована и задаётся Маркетингом в диапазоне 1–5%.

**ФТ-03.** Окно выбора открыто с 25-го числа до последнего дня месяца включительно, до 23:59. Выбор действует на весь следующий календарный месяц.

**ФТ-04.** До закрытия окна клиент может менять выбор без ограничений. После закрытия окна выбор фиксируется и не меняется до конца следующего месяца.

**ФТ-05.** Клиент может в любой момент отказаться от участия в программе в разделе «Кэшбэк» → «Настройки». После отказа кэшбэк за текущий месяц не начисляется, выбор категорий удаляется.

### 4.2 Расчёт кэшбэка

**ФТ-06.** Кэшбэк начисляется за операции покупки со статусом «успешно» в торговых точках, MCC которых входит в выбранные клиентом категории. Список MCC по категориям: TBD (запросить у ПЦ).

**ФТ-07.** Учитываются покупки на сумму от 1 000 ₸. Операции в иностранной валюте, снятие наличных, переводы, пополнение кошельков и оплата услуг через приложение не учитываются. Ограничения по типам карт см. ФТ-19.

**ФТ-08.** Кэшбэк по операции = сумма покупки × ставка категории. Результат округляется вниз до целого тенге.

**ФТ-09.** Максимальная сумма кэшбэка составляет 15 000 ₸ в месяц на клиента по всем его картам. При достижении лимита кэшбэк по остальным покупкам месяца не начисляется.

**ФТ-10.** Операция относится к отчётному месяцу по дате операции.

### 4.3 Начисление и уведомления

**ФТ-11.** Расчёт за отчётный месяц запускается автоматически 1-го числа следующего месяца в 02:00 UTC. CBS забирает реестр операций из ПЦ и считает кэшбэк по каждому клиенту.

**ФТ-12.** По итогам расчёта CBS передаёт в АБС поручение на зачисление по каждому клиенту. Зачисление выполняется 5-го числа месяца, следующего за отчётным.

**ФТ-13.** Если при вызове АБС возникла ошибка, задание расчёта перезапускается целиком через 30 минут, не более 3 попыток. После 3 неудачных попыток создаётся инцидент в Jira SD.

**ФТ-14.** После зачисления клиенту отправляется push-уведомление: «Вам начислен кэшбэк {сумма} ₸ за {месяц} по карте *{последние 4 цифры}».

**ФТ-15.** Клиент видит в приложении историю начислений за последние 12 месяцев: месяц, категория, сумма покупок, сумма кэшбэка, статус. КЦ видит ту же историю в CRM по ИИН клиента.

**ФТ-16.** Маркетинг в админ-панели CBS создаёт и редактирует категории, ставки и лимит кэшбэка. Изменения вступают в силу со следующего отчётного месяца.

## 5. Нефункциональные требования

**НФТ-01.** Раздел «Кэшбэк» в приложении должен открываться быстро, интерфейс выбора категорий должен быть интуитивно понятным.

**НФТ-02.** CBS должен выдерживать высокую нагрузку в период окна выбора (25-е число – конец месяца).

**НФТ-03.** Доступность CBS: 99,5% в месяц без учёта согласованных регламентных работ.

**НФТ-04.** Все даты и время в интерфейсе, отчётах и правилах программы указываются по времени Алматы (UTC+5).

**НФТ-05.** Логи запросов к API CBS (метод, URL с параметрами, код ответа, время ответа) хранятся 90 дней в ELK.

**НФТ-06.** Доступ сотрудников Маркетинга в админ-панель: через AD Банка, роль CASHBACK_ADMIN. Все изменения ставок и лимитов пишутся в журнал аудита.

## 6. Интеграция

### 6.1 API CBS

API доступно мобильному приложению через API Gateway (авторизация по токену сессии клиента) и CRM (сервисная учётная запись).

| № | Метод | Путь | Назначение | Ответ |
|---|---|---|---|---|
| 1 | GET | /api/v1/cashback/categories?month=YYYY-MM | Список категорий и ставок на месяц | 200, массив категорий |
| 2 | GET | /api/v1/cashback/activate | Подключение клиента к программе | 200 |
| 3 | POST | /api/v1/cashback/selection | Сохранить выбор категорий, тело: month, category_ids[] | 201 |
| 4 | GET | /api/v1/cashback/selection?month=YYYY-MM | Текущий выбор клиента | 200 |
| 5 | GET | /api/v1/cashback/history?iin={ИИН}&from=YYYY-MM&to=YYYY-MM | История начислений (приложение и CRM) | 200, массив начислений |
| 6 | POST | /internal/v1/accruals/run | Ручной запуск расчёта за месяц (для поддержки) | 202 |

При ошибке валидации (окно выбора закрыто, неизвестная категория) метод 3 возвращает 200 с полем `error` и текстом ошибки для показа клиенту.

Поля элемента ответа метода 5:

| Поле | Тип | Описание |
|---|---|---|
| month | string | Отчётный месяц, YYYY-MM |
| category_code | string | Код категории |
| purchase_total | integer | Сумма покупок в категории, тиын |
| cashback_amount | integer | Сумма кэшбэка, тиын |
| status | string | PENDING / ACCRUED / FAILED |

### 6.2 Внешние системы

| Система | Взаимодействие | Описание |
|---|---|---|
| ПЦ (Way4) | Файл CSV по SFTP | Реестр операций по картам за календарный месяц по времени сервера ПЦ (UTC). Готов к 01:00 UTC 1-го числа. При отсутствии файла CBS повторяет попытку каждые 15 минут до 06:00 UTC, затем создаёт инцидент |
| АБС (Colvir) | REST, POST /colvir/api/v2/transfer | Зачисление кэшбэка на карточный счёт с транзитного счёта программы. Синхронный вызов, таймаут 10 с |
| Push-сервис | REST, POST /notify/v1/push | Отправка push-уведомлений клиенту |

## 7. Данные

Таблица `cb_selection` (выбор категорий):

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| client_id | uuid | да | ID клиента в CBS |
| month | char(7) | да | Месяц действия выбора, YYYY-MM |
| category_ids | int[] | да | Выбранные категории (1–3) |
| updated_at | timestamp | да | Время последнего изменения выбора |

Таблица `cb_accrual` (начисления):

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| accrual_id | uuid | да | ID начисления |
| client_id | uuid | да | ID клиента в CBS |
| iin | char(12) | да | ИИН клиента |
| card_number | varchar(16) | да | Номер карты, на счёт которой зачислен кэшбэк |
| month | char(7) | да | Отчётный месяц |
| cashback_amount | decimal(12,2) | да | Сумма кэшбэка, тенге |
| status | varchar(10) | да | PENDING / ACCRUED / FAILED |
| accrued_at | timestamp | нет | Время зачисления в АБС |

Параметр `cb.monthly_limit` (лимит кэшбэка в месяц на клиента): 10 000 ₸, меняется Маркетингом в админ-панели.

Таблица `cb_accrual` ежедневно выгружается в CRM Маркетинга для сегментации клиентов и персональных предложений.

## 8. Критерии приёмки

| № | Сценарий | Ожидаемый результат |
|---|---|---|
| КП-01 | Клиент 27.01 выбирает «Кафе и рестораны» (5%) и «АЗС» (3%) | Выбор сохранён, в феврале кэшбэк начисляется по обеим категориям |
| КП-02 | Покупка на АЗС на 8 990 ₸, ставка категории 3% | Кэшбэк по операции 270 ₸ |
| КП-03 | Клиент выбирает 4 категории на март | Выбор сохранён, кэшбэк в марте начисляется по всем 4 категориям |
| КП-04 | За месяц уже начислено 14 800 ₸, покупка в кафе на 10 000 ₸, ставка 5% | Кэшбэк по операции 500 ₸ |
| КП-05 | Покупка на 1 000 ₸ в выбранной категории | Покупка не учитывается, так как сумма должна быть свыше 1 000 ₸ |
| КП-06 | Покупка в выбранной категории в USD | Кэшбэк не начисляется |
| КП-07 | Клиент не подключён к программе и открывает раздел «Кэшбэк» | Отображается кнопка «Подключить» и условия программы |
| КП-08 | Начисление за январь | Сумма зачислена на карточный счёт до 5-го рабочего дня февраля, клиент получил push |
| КП-09 | Сотрудник КЦ открывает историю по ИИН клиента | Отображается история начислений за 12 месяцев |

## 9. Открытые вопросы

- Подключение кредитных карт во второй фазе: решение Маркетинга.
- Стартовые ставки по категориям: Маркетинг до 01.12.2026.
