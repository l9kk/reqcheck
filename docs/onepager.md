# reqcheck: агент ревью требований

**Задача.** Найти дефекты в ТЗ до начала разработки: противоречия, неоднозначности, непроверяемые
формулировки, пропуски. Ручное ревью занимает часы и зависит от того, кто его делает.

**Решение.** Одна команда `python -m reqcheck <ТЗ> -o report/report.md`. На входе PDF, DOCX, MD или TXT.
На выходе отчёт MD + PDF + JSON: замечания с дословными цитатами и номерами строк, уточняющие вопросы
автору с вариантами ответа, проверка каждого требования и набора в целом, заполненный чек-лист, вердикт.

## Как устроен агент

| Роль | Что делает |
| :--- | :--- |
| Reader | читает файл, диагностирует битые входы (пароль, скан, не ТЗ) |
| Segmenter | код режет документ с номерами строк, модель решает, что является требованием |
| Linter | правила кода: размытые слова, заглушки, GET для записи, данные карт в логах |
| Auditor | каждое требование по 9 свойствам ISO/IEC/IEEE 29148 п. 5.2.5 |
| CrossChecker | набор целиком: пересчёт критериев приёмки, конфликты правил, покрытие, интеграция |
| Critic | убирает ложные и повторные замечания, ставит важность |
| Clarifier | вопросы автору: кому, что блокирует, варианты, ответ по умолчанию |

- Стандарты как данные: `criteria.toml` (ISO 29148, IEEE 830), из него собираются промпты.
- Защита от галлюцинаций: замечание без цитаты, найденной в документе, отбрасывается кодом и пишется в трассу.
- Защита от инструкций внутри документа: текст ТЗ для модели только данные.

## Точность (эталоны составлены вручную)

| Документ | Найдено (авто / вручную) | Критичные | Обязательные | Точность |
| :--- | :--- | :--- | :--- | :--- |
| Выданное ТЗ, 40 дефектов | 27 / 23 | 6/6 | 13/13 | 97% |
| Второе ТЗ, 18 дефектов, эталон до прогона | 15 / 14 | 4/4 | 8/8 | 71% |
| Только правила кода, без модели | 11/40 | - | 9/13 | 93% |

Прогон на выданном ТЗ: около 2 минут, 6 запросов к модели, повтор из кэша бесплатно.
13 видов повреждённых файлов: агент не падает, пишет диагностику и код выхода 2.
