# reqcheck

Агент проверяет ТЗ до разработки: находит дефекты требований по ISO/IEC/IEEE 29148 и задаёт автору
вопросы с вариантами ответа. Свёрстанная версия: [`onepager.pdf`](onepager.pdf).

## Результат на выданном ТЗ (claude-opus-5-5)

- **40 из 40** дефектов из нашего списка (строгая проверка: 39).
- **6 из 6** критичных распознаны как критичные, в каждом из 3 прогонов.
- **0 ложных** из 55 замечаний: 48 реальные дефекты, 7 дубли и мелочи.
- **14 минут** вместо инспекции: 3-4 ревьюера, около часа каждый; около 1 110 ₸ за прогон.

Числа и команды для их проверки: [`RESULTS.md`](../RESULTS.md).

## Как работает

Reader (код) -> Segmenter -> Linter (код) -> Auditor -> CrossChecker, EdgeCaser, WholeDoc -> Critic ->
Clarifier -> Reconciler -> отчёт. Вход PDF, DOCX, MD, TXT. Отчёт MD, PDF, JSON, HTML. Номер строки к
каждой цитате ставит код.

## Пример из отчёта

> 39 «На карту приходится максимум один такой push за календарный месяц»
> 40 «следующее достижение вызывает push независимо от истории предыдущей настройки»

- **D-01**, критично: строки 39 и 40 противоречат друг другу.
- **Q-01**, бизнесу: отправляется ли второй push в том же календарном месяце? Три варианта с тестом, рекомендован (б).

## Зачем

Инспекция этого ТЗ командой из 3-4 ревьюеров, около часа каждый: 8 000-15 900 ₸. Агент: 14 минут,
1 110 ₸. Дефект требований, найденный только на тестах, в 21-78 раз дороже (NASA, 2004).

## Что получает команда

- Вердикт: начинать ли разработку и что исправить первым.
- Цитата и номер строки к каждому замечанию.

## Запуск

```bash
pip install -r requirements.txt
python -m reqcheck <ТЗ> -o out/report.md
```

Повтор на выданном ТЗ без ключа, из кэша: команда в [`RESULTS.md`](../RESULTS.md).
